# 競輪AI：決まり手×選手×ラインの研究ロジック

既存の統合式・会社方式・リスク部・高配当部・サイト・note予想は変更しない。今回の追加は研究専用。

## 予測の構造

- 既存の凍結済み3連単確率分布 `P_old(a,b,c)` 全件を基準とする。
- 確定済みの過去実レースから `P(1着決まり手, 2着決まり手 | 級班, 車数, 競輪場)` を推定する。母数不足の会場は全国へ縮約し、時間帯別の希薄セルはあえて使用しない（既存検証で2着組合せの精度が悪化したため）。
- その級班・競輪場の組合せ確率を、候補1着選手が過去に **1着に入った際の実際の決まり手**、候補2着選手が過去に **2着に入った際の実際の決まり手** に掛け合わせる。順位別の実績をその順位の能力と混同しない。実績の少ない選手は20観測分の全国事前値で縮約する。
- 全車の「予想ライン」が構造検証済みの場合に限り、番手／ライン先頭・追走の仮説スコアを付与できる。**これはデータから学習した確率ではなく、事前指定の未較正スコア**。履歴上の予想ライン位置が欠落／不整合なら使わない。
- 1→2着の候補組に同じ再重み付けを掛け、3着候補間の既存条件付き順位は保持する。したがって3着の改善は学習済みと主張しない。

`P_new(a,b,c) ∝ P_old(a,b,c) × ScenarioScore(a,b)^α`、全3連単を正規化。`ScenarioScore` は確定決まり手組合せの確率分布と候補選手の事前の実績、任意のライン仮説から得る**倍率**であり、それ自体は的中確率ではない。

## 事前に固定する対照群

| 方式 | シナリオ係数 α | ライン仮説係数 |
| --- | ---: | ---: |
| 旧統合式（対照） | 0 | 0 |
| 選手の決まり手履歴のみ | 0.35 | 0 |
| 選手履歴＋ライン（弱） | 0.35 | 0.30 |
| 選手履歴＋ライン（強） | 0.70 | 0.30 |

係数は仮説として**事前固定**し、ホールドアウト結果を見て更新しない。上位3・8・12・18点の的中率、全3連単確率の対数損失、1着／1→2着首位の正解、従来から救えた／失ったレース、級班・車数・ライン確認有無、日単位ブートストラップで比較する。結果が悪ければ却下する。

## 漏洩対策・限界

1. 2025-10-09より前の公式決まり手のみで学習し、2025-10-09〜2026-10-08の元の **凍結済み** 全3連単予測を使用。公式の当該年の正解ラベルを学習に含めない。
2. `predict` は過去レースの `finish_pos`, `result_...`, `payout` を読み込まない。予想を圧縮JSONLに書きSHA256を固定した後、別の `assess` 処理だけが着順を開く。対象レースは同じものをペア比較する。
3. 歴史出走ファイルの特徴取得タイムスタンプが必ずしも発走締切前と確認できないため、これは**遡及データを使った研究**。新しい未使用期間の独立検証でも、発走前実運用の的中率でもない。
4. 過去の締切前オッズや購入実績が未取得。**回収率／万車券の的中改善は検証できない**。本番昇格・有料販売への採用を自動化しない。
5. 2026-10-13の初回59,857レースの公式アーカイブに含まれる `first_line_role`・`second_line_role`・`forecast_suji` は全て欠損。これらを結果から補完して学習しない。ライン評価に使う情報は別の出走者履歴に存在する予想並びだけ。
6. 公開結果の二次データを商用利用するときは提供元の利用条件を確認。Gambooの転載データは取り込まない。

実行: `method-scenario-research` ワークフロー。元の実レース履歴のActionsキャッシュ、既存の凍結済み予測成果物、公式決まり手実績成果物が欠けた場合は停止する。サンプルを実績に代入しない。

[監査 Actions](https://github.com/rokuda6898-jpg/keirin-ai-auto/actions/runs/38351073569) 成功。凍結済みの元履歴 SHA-256 `7c7493e6eb6b1dfbf085afa8fade8de73c2bb2c458b135af7fb8c0009c154333` を保持。

### 同一既存1年予測での追加の**研究**条件（検証結果を見ての採用禁止）

従来の4方式は結果再現用に維持する。追加2方式は `archive_geometry_010` と `archive_geometry_030`。

- これらは**検証済みの予想ラインではない**。保存された `line_id`・`line_position` が全車分重複なく内部整合し、全車の `source_url` が同じ正規のWINTICKET racecardページで、かつ `line_verification_status` が明示的な *incomplete / ambiguous* ではなく欠落しているケースに限定する。
- この未検証ラインを `verified` へ書き換えない。`line_structured_unverified` として分離し、弱い係数（0.10または0.30）だけ付与。構造不正・ソース不明・明示的エラーは **不使用**。
- 元3連単フル分布のSHAと学習日付を固定し、正解列を一切読み込まず予測を保存してから評価。既存方式との上位3/8/12/18点の同レース比較、条件別レース数、失った/救えたレースを残す。
- **最重要制約**：履歴からはライン情報の取得時点を証明できない。この結果は探索的・遡及的であり、成績が良くても本番/販売へ統合しない。新しい発走前固定データで再現しなければ昇格できない。
