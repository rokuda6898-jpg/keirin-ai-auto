# 部署と全方程式の統合研究

これは事前予想を保存して比較する研究モデルです。７部署、リスク部の現行ロジック・買い目、社長の最終判断は変更しません。購入承認も自動採用もありません。「式を実装した」「学習した」「的中率が改善した」は別の状態です。

## 組み込む式と意見

| 成分 | 統合への渡し方 |
| --- | --- |
| 元の着順モデル | 年間知識による部署補正前の１・２・３着評価から全着順へ展開 |
| 部署の２・３着評価を保持する① | データ・展開・ライン・リスク部の保存済み評価。３専門部署の従来方式も対照成分として保持 |
| 順位別・条件付き市場支持② | 同一時刻の全３連単が揃うときに、既存の条件付き・①＋②の分布を使用 |
| 専門展開補正 | 保存済みの部署別展開分布を使用。①・②の独立実験は維持 |
| 初期の市場補正式 | 逆オッズを基準に個人・組み合わせ特徴を学習する既存式 |
| 初期の先着関係式 | 既存の選手間先着モデル。単一の強さの差に依存する限界があるため比較成分として明示 |
| 初期の隊列頻度式 | 観測した途中隊列の既存モデル。最終順位頻度に強く依存する限界があるため比較成分として明示 |
| 新しい組み合わせ式 | 各部署の着順評価、検証済みラインの先頭・番手・３番手、選んだ１・２着と３着の位置関係、別線先行選手の観測情報、風など |
| 新しい条件付き隊列式 | 現レースの選手・ライン情報に条件付けたスタート→打鐘→最終バック→着順の遷移 |
| 予想部・軍師・高配当部を含む全７部署 | 同じ処理回の提出した３人の並びを組み合わせ式の特徴として保存。１案しかない意見に架空の確率を付けない |

高配当部の価格未確認シナリオは、100倍以上の買い目とは区別します。途中隊列が未観測なら、隊列成分は使いません。記録不足を想像で補いません。

## 最終的な確率と買い目の式

全着順を `t=(a,b,c)`、保存済み事前情報を `x` とします。

```
組み合わせ式: p_joint(t | x) = softmax_t(β・φ(x,a,b,c))
隊列式:       p_path(f | x) = Σ(s,b,k) p(s | x) p(b | s,x) p(k | b,x) p(f | k,x)
統合前:       m(t | x) = Σ(g∈利用可能) w_g p_g(t | x) / Σ(g∈利用可能) w_g
統合後:       P(t | x) = m(t | x)^(1/T) / Σ(u) m(u | x)^(1/T)
買い目集合:   S* = argmax_S Σ(t∈S) P(t | x)
```

`φ` は明示した特徴です。未取得値には別の欠損指標を付け、実績ゼロと区別します。ライン未確認を同ラインと扱いません。３着は「１・２着を除いて残りを割る」だけでなく、選んだ組み合わせとライン位置の相互作用を使います。隊列式は観測データの統計モデルであり、速度・消耗の物理シミュレーションではありません。

`g` は同一予測をまとめた成分の集まりです。別名・別部署の完全な複製でも１枠にまとめ、複製を増やして事前の重みを増やせません。将来、同じ枠の式が異なる予測を出した場合は、その枠の中で異なる分布を等分します。重みは非負・合計１。組み合わせ用の期間で対数損失を小さくしつつ、似た誤りへの偏りと重みの過度な集中を抑えます。票数・部署数を根拠数として扱いません。

`S` は本線・穴それぞれリスク部と同点数（１〜12点）、１点100円。穴は予想時点の100倍以上、本線は100倍未満です。候補確率0.001以上かつ有効な事前価格があるものを確率順で選択。候補不足なら比較不成立です。旧実験の期待値条件は残し、統合研究の確率順比較とは区別します。ここで求めるのは固定点数での推定的中確率であり、回収率を保証する式ではありません。

## 時間の分離

過去180日、最大900レースから、JSTの日付をまたがせず古い順に３期間へ分けます。

1. A期間で個別モデルの係数を学習。
2. B期間で、Aで学習したモデルの予測から組み合わせの重みを学習。
3. C期間で温度 `T` を選び、確率の過信・過小評価を補正。

各期間50レース・７日以上が必要です。合計最低150レース・21日ですが、分割後も条件を満たす必要があり、件数だけでは開始できません。これは学習開始の最低条件で、精度・検出力の保証ではありません。校正係数を当てはめた段階で「校正が検証済み」とは表示しません。

モデルは日ごとに最初の１個を固定。前日までに保存した入力と、前日までに観測済みの公式結果だけを使用します。予測日の情報や同日結果は学習しません。評価したレースは後日の学習に利用する事前指定の日次更新方式です。隊列の学習はA期間の実観測のみ、出走人数ごとに最低50レース・７日。動画の自動観測機能は今回含みません。

新しい７部署入力は、導入後の同じ予測処理回に保存します。既存の過去データへ意見を後付けして学習件数を作りません。

## 比較の変更点

- 全方式で先に最新の共通スナップショットを固定。方式が欠けても古い都合のよい予想へ戻らない。
- リスク部と買い目を比較できない見送りレースでも、全着順確率の誤差を市場支持・元のモデルと比較。
- 対数損失を `１着 + ２着|１着 + ３着|１・２着` へ分解。買い目の外れも同様に分ける。
- 的中率と回収率を分離。最大の払戻が回収額に占める割合と、その払戻を除いた回収率をリスク部にも表示。
- 出走人数・クラス・市場の完全性・部署意見の欠損・候補不足・収集失敗を保存。対象の違う行同士を単純に順位付けしない。
- 市場、部署、先着、隊列、組み合わせの成分を外す比較版を保存。ただし再学習しない除外であり、残った組み合わせ式にも部署・市場由来の特徴がある。完全な特徴除去・因果的な寄与の証明ではない。

単勝的な人気を２・３着支持へ流用したり、３着の固定重みや買い目数を増やしたりする変更ではありません。

## 社長への採用確認

探索結果は採用の証拠と区別します。学習後、人が式と目標改善幅を確認し、将来のJST午前０時から56日間を登録します。登録は自動実行しません。式・元の予測処理を途中変更した確認試験は無効です。

56日後に本線・穴の各比較500レース・28日以上を要求します。足りなければ証拠不足のまま終了し、勝てるまで延長しません。日付の空白も残した７日ブロックの再抽出で、的中率差と回収率差の区間を別々に計算します。登録回数 `n` へ `0.05/[n(n+1)]` を配り、さらに本線・穴×２指標へ分けます。尾部の再抽出回数が足りなければ判定しません。

これらは依存構造を仮定する近似評価です。多重比較への配慮があっても、将来成績や検出力の保証にはなりません。目標改善幅を支持する下限、回収率、確率校正、対象の偏り、高配当への依存を人が確認します。自動採用・自動購入は実装していません。

## 運用と記録

`fusion_lab.py report` は保存済み記録の集計のみ。`train` は当日のモデル固定のみ。過去時刻で予想を作成するCLIはありません。事前登録は `register-confirmation --starts-at <将来のJST午前０時> --target-hit-delta <目標改善幅>`。学習済みモデルがなければ拒否します。

`annual_fusion_inputs / models / ledger / attempts / confirmations.jsonl` は追加保存。予測・結果・学習元・実観測の参照を検証し、固定モデルから予測を再現して照合します。価格の鮮度、締切５〜40分前、計算完了時刻を再確認。並行する更新でも記録を合流し、公開資料を作り直します。レポート生成で新規予想は作りません。

今回の実装で旧式の弱点が数学的に消滅したわけではありません。旧式を対照として残し、新しい式と統合による改善を将来の事前記録で検証します。
