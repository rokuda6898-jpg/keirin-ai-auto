# NEXUS 年間回収率改善の購入判定

更新日：2026年10月20日。方針 ID：**nexus-value-ev-v1**。

## 目的と現在地

**全レースの予想と既存のフォーメーションを残し、購入するかを期待回収率で判定する。** 元の全着順確率 q、選手の印、S/A/B、買い目は変更しない。購入判定用の確率 p_bet を別に校正し、各点100円と5,000〜10,000円の配分をそれぞれ評価する。

これは固定した初期候補の仕様であり、年間100%超を達成した方式ではない。判定核は研究用の独立モジュールとして扱い、本番予想の推奨や過去の保存済み買い目を上書きしない。元の年間集計は2025年10月9日〜2026年10月8日の27,351R、回収率77.493%。元明細を再現できていないため、この仕様の年間回収率は未算出である。[元のモデル記録](../models/nexus53/manifest.json)

10点案は最初の32Rで108.72%だったが、追加7Rでは65.43%に低下した。合算39Rは100.95%でも、追加7Rの従来方式148.42%に及ばず、年間の採用根拠にはならない。[追加7Rの記録](../outputs/nexus_forward_initial_check_2026-10-20.json)

## 購入判定の固定ルール

### 1. 予想確率と市場の評価を、過去の独立期間で校正する

レースの有効な全3連単を t とする。同一時点の全オッズ O から、市場の参考分布 m を作る。

    m[t] = (1 / O[t]) / Σu(1 / O[u])
    p_bet[t] = exp(a × log(q[t]) + b × log(m[t])) / 正規化定数

a、b の2係数を、予想モデルの学習に使っていない過去の校正期間で、多クラスの log loss を最小化して求める。対象レースの結果、確定オッズ、将来の払戻は入力にしない。元の q は不変で、p_bet を別の配列として保存する。

m はオッズから作った参考分布であり、実測された真の的中確率ではない。正規化しただけで利益が生まれるわけでもない。市場だけを使う場合、各買い目の m[t] × O[t] は共通の 1 / Σu(1 / O[u]) になる。モデルに市場を上回る予測力があるかを別期間で検証する必要がある。

校正の学習データを元モデルの学習データと分けるのは、学習済みデータ上で良く見える確率をそのまま信じないためである。[scikit-learn：確率校正](https://scikit-learn.org/stable/modules/calibration.html)

**上位12点だけの確率やオッズを、全着順の分布として正規化しない。** 全着順 q、全市場オッズ、同じ出走選手、同じ時点の証拠を要求する。ゼロ・欠損・上限表示のオッズがあり、完全な市場分布を作れなければ未評価とする。結果を見てから使えるオッズだけを拾い直さない。

### 2. 締切前5分以内のオッズだけを使う

次の条件を別々に満たす。

| 条件 | 初期仕様 |
| --- | --- |
| オッズ取得から判定まで | 0〜300秒 |
| オッズ取得からそのレースの締切まで | 0秒超〜300秒 |
| 判定と保存・公開 | オッズ取得後、締切の60秒以上前 |
| 同一性 | レース ID、日付、締切、出走車番、元予想、モデルと入力の証拠が一致 |
| 結果の混入 | 取得時点で結果・確定オッズ・返還や中止の確定情報がない |

取得直後に判定しても、そのオッズが締切の何時間も前なら使わない。逆に締切5分前のオッズでも、締切後に計算した判定を事前購入として保存しない。証明できない時刻は補完せず未評価とする。ここでいう公開証拠は、自分で記入した日時だけではなく、保存内容のハッシュと変更できない公開記録を対応させたものを指す。

### 3. オッズが20%下がる条件でも、期待回収率110%以上を求める

購入予定額を s[t]、総額を B として計算する。

    stress_odds[t] = 0.80 × 表示オッズ[t]
    期待回収率 = Σt(p_bet[t] × stress_odds[t] × s[t]) / B
    購入候補の条件：期待回収率 >= 1.10

**0.80と1.10は、先に固定する未検証の仮説である。** 0.80はオッズ下落の統計的な下限でも保証値でもなく、1.10は実際の回収率110%を約束する値でもない。これらを過去646Rや39Rの成績が高くなるまで動かさない。変更する場合は別バージョンにし、変更後の未使用期間で確認する。

表示オッズは払戻倍率として使う。見積払戻はオッズ×購入額で求め、実精算では公式払戻金を使う。[KEIRIN.JP：オッズを見る](https://keirin.jp/pc/static/beginner/basics/odds.html)

### 4. フォーメーション全体を、購入か見送りかに分ける

既存フォーメーションの重複を除いた全買い目を残す。都合の良い車番や人気薄だけを抜き出して新たな成績を作らない。1着固定の有無は元の予想に従う。

| 表示する方法 | 判定する購入額 | 条件 |
| --- | --- | --- |
| 各点100円 | 全買い目に100円。B＝点数×100円 | その配分で期待回収率110%以上 |
| 5,000〜10,000円 | 全買い目に100円単位。予算ごとに独立判定 | 期待回収率110%以上、かつどの買い目が当たってもストレス条件の見積払戻が予算以上 |

配分は元の全買い目を保持し、最少の見積払戻を高める。連続額の配分で成立するかの目安は Σt(1 / stress_odds[t]) <= 1 だが、100円刻みではそれだけで十分ではない。実際の整数配分で各買い目の見積払戻を確認する。成立しない予算は配分を提示しない。的中しなかった場合の損失をなくす制約ではない。

予算を5,000円から10,000円へ変えたら、その予算の配分と期待回収率を計算し直す。結果の集計も同じ予算の保存済み購入額で行う。各100円版と配分版を同じ購入判定にしたり、片方の回収率をもう片方に表示したりしない。

## S/A/B と購入判定の表示

現行のS/A/Bは元の選択買い目へのモデル支持度による表示区分である。S＝合計0.65以上、A＝0.45以上、B＝それ未満で、実測的中率を校正した区分ではない。[現在の表示実装](../src/nexus_model/forecast_confidence.py)

Sだから必ず購入、Bだから必ず見送りとはしない。全レースに従来の印・自信度・フォーメーションを表示し、購入判定を別に示す。

| 状態 | 意味 |
| --- | --- |
| 購入候補 | 必要な証拠が揃い、その購入額で固定条件を通過した |
| 見送り | 評価できたが、期待回収率または配分条件を満たさない |
| 未評価 | 校正、オッズの鮮度、全着順、保存・公開の証明などが不足している |

未評価を低い期待値として扱わず、理由を保存する。予想の的中率と、購入したレースだけの的中率・回収率・購入率は別に報告する。

条件付きの初回オッズ137Rは、締切までの残り時間が中央値345.452分、最短5.322分だった。配分が成立した129Rのうち、的中した56Rで「公式払戻÷保存オッズでの見積払戻」を再計算すると、中央値は0.756630、56R中45Rが1未満、33Rが0.80未満だった。比率の最小は0.106811、最大は2.937255。既存の初回配分監査と一致している。[同監査のconditional集計と各R記録](../outputs/nexus_value_data_audit_2026-10-20.json)

この比率は**的中した56Rに条件を絞った診断**で、全買い目のオッズ下落率を推定したものではない。NEXUS年間77.493%の原因を確定したものでもない。20%下落を見込めば十分だという根拠には使えない。別ファイルの近接保存5Rも確認したが、同じ137Rの中の追加時点で、最短6.924分前だった。初回137Rの集計へ混ぜていない。

NEXUSの1Rは後続の生ページにある締切前オッズであり、元の保存済み配分が使った時刻とは異なる。全qの事後再現を元の事前公開値と呼ばず、正確な再現時刻・元入力時刻・元予想時刻を残す。この39Rと条件付き646Rを合算して校正済みの年間実績にしない。

## 年間を通した評価の手順

### 期間とデータを先に固定する

年次の開始日、終了日、全開催のレースID一覧、元モデルのバージョン、校正方法、上記の購入条件、予算を、結果を評価する前に保存する。元の27,351Rに対する改善を名乗る場合は、その正確な元ID一覧との一致が必要である。新しい1年間の記録なら、別の期間・別の評価IDとして示す。

初期の時系列評価案は、月ごとに校正を更新し、直前180日までの独立した予測と、その時点までに確定・保存された結果だけを使って次の月を評価する方法とする。期間の境界は日本時間の暦日で作り、レースをランダムに分割しない。開催数が日ごとに異なるので、単純に同じ件数に切って同じ期間と見なさない。過去だけで学習して後続期間を評価する考え方を使う。[scikit-learn：TimeSeriesSplit](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.TimeSeriesSplit.html)

### 年初の校正準備期間を隠さない

元モデルは2025年10月8日までを学習期間に含む。**同じ固定モデルを厳密に保つ場合、独立した校正期間はその学習終了後に置く必要がある。** 元の年次期間の冒頭は校正準備・未評価になり、同条件で年間全体を独立評価した成績とは呼べない。学習期間を最終モデルで再計算しても、独立した校正データにはならない。[元モデルの学習期間](../models/nexus53/manifest.json)

年間初日から評価する別候補を作るなら、モデルの学習を早く終えて、その後に独立した校正期間を確保する。または、過去だけで学習したモデルのOOF予測を使う手順そのものを、別のモデル・校正方針として固定して検証する。古いOOFがあるだけで、学習内容が異なる最終モデルにも校正が通用するとみなさない。今回の判定核は同じモデルのmanifest SHAと、モデル学習終了後の校正開始日を要求する。

年初にその証拠がない場合、準備期間は「校正不足・未評価」として全レース一覧と対象日数に残す。後半だけの回収率を年間回収率と呼ばない。未評価をEVによる見送りに置き換えず、評価開始日、予想表示数、購入判定ができた数、購入数、未評価数を併記する。

### 判定と精算を分ける

判定処理は締切前入力だけを受け取り、買い目・購入額・条件・理由・時刻を保存する。結果処理は後から公式払戻だけで精算する。外れを落とさない。的中レースだけの平均倍率を回収率にしない。同着による複数の払戻、取消・返還・中止も、そのレースの保存購入額に対して処理する。

    実回収率 = 合計の実払戻金 / 合計の実購入額
    的中率 = 的中した購入レース数 / 実際に購入した有効レース数
    購入率 = 購入したレース数 / 期間内の対象レース数

返還がある場合は、総購入額・総受取額に加え、返還を除いた購入額・的中払戻額を保存する。方式の比較では同じ会計定義を使う。購入額0のレースを的中に数えず、購入0件の回収率はnullとする。各100円版、5,000円版から10,000円版までを独立した年次成績として報告する。

### 年間100%超の採用判定で必要な項目

以下は年間データが揃った後の評価・採用条件であり、今回満たした実績ではない。

1. 固定した連続1年間のID一覧と一致し、すべてのレースに予想・購入判定・未評価理由を残す。年初を含む独立した校正と、締切前の意思決定を証明する。
2. すべての購入を公式結果で精算し、各購入方法の年次回収率が100%を超える。同じ年間対象で従来方式も再計算し、投資額・払戻・収支・購入率を併記する。
3. 月ごと・四半期ごとの推移、最大の資金減少、最大払戻への依存を報告する。勝った月だけを選ばない。
4. 最大払戻の1Rを両方式から除いた感度分析でも100%超が残るかを確認する。除いた成績を主成績にはしない。
5. 日や開催のまとまりを保つブロック再標本化で回収率の区間を出し、95%区間の下端が100%を超えるかを採用判断に加える。この区間も将来の利益を保証しない。
6. 途中で試した候補数、条件変更の履歴、使用済みの検証期間を保存する。同じ年の結果を見て再調整したら、その年は開発用と明記し、次の独立期間を確認する。

## 必要なデータ契約

保存単位は「1レースの予想」「複数時点の市場」「締切前の判定」「確定後の結果」を分ける。公開用の集計だけでなく、ハッシュで元の記録へ戻れるようにする。次は年次監査に必要な意味上の項目で、CLIが受理する正確なキーは検証器の契約に従う。

| 記録 | 必須の内容 |
| --- | --- |
| 年次一覧 | 評価ID、開始・終了日、対象race_idの完全な一覧、提供元とSHA-256 |
| レース | race_id、日付、競輪場、R番号、モーニング等の区分、出走車番、発走・締切時刻 |
| 元予想 | 元qと車番の順序、全順列数、元の完全なフォーメーションと重複除去済み買い目、印、S/A/B、予想生成時刻 |
| モデルと入力 | モデルID・manifest SHA、モデル学習の終了境界、入力と履歴のSHA、入力取得時刻、履歴の最終日、元原本のURI |
| 再現の証拠 | 元の保存・公開時刻、変更できない公開コミット、再現時刻、元買い目・確率との一致、当時の全q直接保存の有無 |
| 市場 | 取得時刻、全有効3連単のオッズ、100円単位、欠損・上限・取消の状態、race_id、出典URLと原本SHA |
| 校正 | モデルSHA、独立性が検証できる校正race_id、期間、各OOFの学習境界、係数、log loss目的、fit時刻、有効評価期間、artifact SHA |
| 購入判定 | policy ID、参照校正SHA、判定・保存・公開時刻、p_bet、0.80と1.10、各予算の購入額と期待回収率、buy/skip/unavailable、理由 |
| 結果 | 公式の的中組と100円当たり払戻、同着・返還・中止、取得時刻、出典SHA、結果の訂正履歴 |
| 精算 | 各保存予算の投資・払戻・返還・収支・的中、未精算理由。結果を使って配分を変更しない |

JSON bundle は schema=1、policy_id=nexus-value-ev-v1。校正artifactは元qに上書きせず、model_manifest_sha256、calibration_start/end、training_cutoff_exclusive、calibration_race_ids/sha256、fit_objective=multinomial_log_loss、coefficients={q, market}、fitted_at、evaluation_start/end、artifact_sha256を保存する。

### 判定核が受け取るbundle

| 入力 | 構造 |
| --- | --- |
| 校正 | schema、policy_id、calibration_start/end、evaluation_start/end、records。各recordにframeとoutcomeを持つ |
| 1レースの判定 | schema、policy_id、frame、calibrator |
| 締切前frame | race（prediction.replay_evidenceを持つ元予想）、input_snapshot（元の保存入力）、market_snapshot（同一入力・出走者の全オッズ）、decision_at、published_at |
| 年次監査 | inventory、assessments、outcomes、calibrator |
| 年次inventory | schema=1、start、end、days、inventory_sha256。各dayにdate、race_ids、source_sha256、complete=trueを持つ |

実行時のcomputed_atは、当時のdecision_atやpublished_atと別に保存する。校正artifactの実際のfitted_atも評価期間の開始前である必要がある。後日の校正を当時の日付に戻さない。元のmanifest JSONはCLIのmanifest指定で読み、同一性を確認する。

各方法の出力はstatus（buy / skip / unavailable）、reason_code、expected_return_multiple、stakes、minimum_stress_return_yenを持つ。flatと、allocated内の各予算を別々に返す。証拠が足りない場合はp_bet=nullとし、元qを校正済みの確率として代用しない。年次の全日・全ID・各方法の判定と公式結果が揃わなければ、年間回収率とannual_100_achievedはnullにする。

## 研究用の実装と実行

[判定モジュール](../src/nexus_value.py)と[検証用テスト](../tests/test_nexus_value.py)を、公開中の予想生成と独立して配置する。

    python src/nexus_value.py fit --input calibration_bundle.json --output calibrator.json
    python src/nexus_value.py assess --input decision_bundle.json --output report.json
    python src/nexus_value.py annual-audit --input annual_bundle.json --output report.json

fitは独立性の証拠を検証して校正係数を保存する。assessは各点100円と予算別の判定を返す。annual-auditは対象期間と全race_idの一致を監査する。入力が足りなければ未評価・不足理由を返し、年次成績や購入候補を補完しない。年次の時系列データ整備と上記の採用評価は、この判定核とは別に必要である。
